白話對照表

AI 開發工具白話圖鑑

那張 IG 圖上的九層、四十七個工具，每一個是幹嘛的，以及它們串起來是一條什麼樣的流程。

原圖：AI CODING AGENT ECOSYSTEM · 40 Tools from Prompt to Production
（標題寫 40 個，實際畫出來是 47 個 —— 這裡照畫出來的算）

這張圖在講什麼

它在講一件事：要把「一個念頭」變成「一個真的在跑的 AI 產品」，中間會經過哪些種類的工具。副標 “from Prompt to Production” 就是這個意思 —— 從你打第一句話，到東西上線。

圖上每一橫排是一種工作，排裡面那六七個圓圈是做同一種工作的不同廠牌。同一排裡通常只會挑一個來用，不是全部都裝。這是整張圖最容易誤會的地方：它看起來像一張購物清單，實際上是一張分類表。

另外，圖左邊那些線把九排全部連回同一個程式碼圖示 —— 意思是這九排最後都是接在同一個專案上，不是九個各自獨立的東西。

最後一個結構上的重點：第 1、2 排跟第 3 到 9 排是兩件不同的事。前兩排是「你請 AI 幫你寫程式」，後面七排是「你寫出來的那個產品，它裡面自己有 AI 在跑」。很多人把這兩件事混在一起，才會覺得這張圖看不懂。

01

基礎模型

Foundation Model

大腦本身。所有 AI 能力的源頭，上面八排都是圍著它蓋的。

流程位置：起點。你不必只選一個 —— 不同工作用不同顆很正常。

ClaudeAnthropic

強在長文推理、讀寫程式、聽得懂拐彎的指令。

GPT-5OpenAI

ChatGPT 背後那顆。通用能力強、周邊生態最大。

GeminiGoogle

Google 的模型，跟搜尋、YouTube、Google 文件那一整套綁得緊。

LlamaMeta

開源。可以整顆下載到自己電腦跑，不用付月費，但要顯卡。

Mistral法國

開源、體積小、跑得快，適合機器規格不高的場合。

DeepSeek中國

開源、便宜，數學和寫程式特別強。

02

AI 寫程式助手

AI Coding Assistant

把模型變成會動手的工程師。這排彼此的差別在一件事：會不會自己開檔案、改檔案、跑指令。有的只會幫你打字，有的能整個專案自己動。

流程位置：你實際幹活的地方。這排的產出物就是「程式碼」。

Claude CodeAnthropic

終端機、VS Code 擴充、手機遙控都是它。會自己讀檔改檔跑指令。

GitHub Copilot

編輯器裡的自動補完 —— 你打一半它接下去。不會自己動整個專案。

Cursor

一整個內建 AI 的編輯器（拿 VS Code 改的）。用它要換掉現在的編輯器。

Windsurf

同類型的 AI 編輯器，Cursor 的直接競爭者。

Cline

VS Code 的開源擴充，做的事情跟 Claude Code 接近，但留在原本的編輯器裡。

Aider

純終端機的 AI 配對工程師，開源、很輕。

03

代理框架

Agent Frameworks

讓好幾個 AI 分工、照流程跑、失敗會重試。當一件事不是問一句答一句，而是「先查資料 → 再判斷 → 再產出 → 錯了重來」，就需要有人管這個順序。這排就是管順序的。

流程位置：產品裡的總指揮。注意這排是「你要自己寫程式」把 AI 串起來，不是裝了就會動。

LangGraph

用「流程圖」定義 AI 的步驟，可以分支、繞迴圈、卡住重來。

CrewAI

讓幾個 AI 各扮一個角色（企劃／工程師／審稿）互相交接工作。

AutoGen微軟

讓多個 AI 互相對話，把問題吵出答案。

OpenAI Agents SDK

OpenAI 官方的 agent 工具包，跟他們家的模型綁得緊。

Google ADK

Google 的 agent 開發套件，綁 Gemini 和 Google Cloud。

Semantic Kernel微軟

把 AI 塞進公司裡既有的舊系統，企業在用的居多。

04

外接介面

MCP Layer

AI 的 USB 孔。讓 AI 不只是會講話，而是真的能碰到外面的東西 —— 檔案、資料庫、GitHub、Slack。MCP 是 Anthropic 訂的規格，現在其他家也照著做，等於這個領域的統一插座標準。

流程位置：產品伸出去的手。沒有這排，AI 只能吐字，碰不到任何真東西。

MCP規格本身

插座的規格書。下面每一個都是照這個規格做的插頭。

FastMCP

用 Python 快速做一個自己的插頭，接你自己的軟體或機器。

GitHub MCP

讓 AI 讀寫 GitHub —— 開 PR、看 issue、推分支。

Filesystem MCP

讓 AI 讀寫本機檔案。有些工具（例如 Claude Code）本身就內建這能力。

PostgreSQL MCP

讓 AI 直接對資料庫下查詢，不用先寫一支程式去撈。

Slack MCP

讓 AI 收發 Slack 訊息，做通知或值班機器人常用。

05

記憶與知識庫

Context & Knowledge

向量資料庫。把大量文件變成 AI 查得動的形狀，解決「AI 不知道我家的資料」。它不是記憶力 —— 它是一個超快的相似度搜尋櫃：你問一句，它從幾萬份文件裡撈出最相關的幾段，塞給 AI 當參考。

流程位置：產品的長期記憶。文件少的時候直接讀檔就好，量大到搜不動才需要這排。

Pinecone

雲端託管，不用自己維護，按月付費。最省事、也最貴。

Chroma

開源、輕，可以裝在自己電腦上。入門最常見的一個。

Weaviate

開源，功能多，支援比較複雜的篩選查詢。

Milvus

開源，專為「上億筆」這種規模設計。

FAISSMeta

是一個函式庫、不是服務。最輕最快，但要自己寫程式包起來。

OpenSearch

傳統搜尋引擎加上向量功能，適合本來就在做站內搜尋的人。

06

執行環境

Runtime & APIs

把寫好的東西變成一個「別人可以呼叫」的服務。程式碼在你電腦上能跑，跟它能 24 小時掛在網路上被人使用，是兩回事。這排負責中間那段轉換。

流程位置：從「我的程式」變成「一個服務」的那一步。

FastAPI

用 Python 寫網路 API 的框架，AI 服務最常見的門面。

Docker

把程式和它需要的環境打包成一個箱子，換台電腦也能原樣跑。

Kubernetes

管理成百上千個箱子，自動擴充、自動重啟。規模大了才需要。

AWS Lambda

不用養伺服器：有人呼叫才跑，跑完就關，按秒計費。

Cloud RunGoogle

同上，Google 版，吃 Docker 箱子。

07

品質把關

Evaluation & Testing

檢查 AI 的產出到底夠不夠好，而不是靠人肉一個一個看。AI 的麻煩在於同一個問題問兩次答案會不一樣，所以不能用傳統「答案對不對」的方式測，要另外一套。

流程位置：橫跨全程。從你在改 prompt 的時候就在用，一路用到上線後。

LangSmith

追蹤每一次 AI 呼叫並打分數。LangChain 官方出的。

TruLens

專門評「AI 的回答有沒有根據」，抓幻覺用的。

DeepEval

像寫程式測試一樣寫 AI 測試，可以接進自動化流程。

Promptfoo

同一個問題用不同 prompt 跑，並排比較哪個寫法比較好。

08

監控觀測

Observability

事後回頭看：花了多少錢、哪裡慢、哪裡出錯。跟上一排的差別在問的問題不同 —— 上一排問「做得好不好」，這排問「跑得順不順、貴不貴」。

流程位置：橫跨全程。這排是唯一能回答「這個月為什麼帳單這麼高」的東西。

Langfuse

開源。記錄每次呼叫的內容、耗時、花了多少錢。

Helicone

擋在你和模型中間幫你記帳，改一行設定就能接。

OpenTelemetry

業界共通的追蹤規格，不綁任何廠商。是標準，不是產品。

Grafana

把數字畫成儀表板和折線圖。你可能在別的地方看過它的畫面。

09

上線部署

Deployment

把做好的東西放到網路上讓別人用。四個都是「租電腦」的地方，差別在規模、價格，還有你想待在誰家的生態裡。

流程位置：終點。

Vercel

網頁一鍵上線，前端專用，最簡單的一個。

AWSAmazon

全球最大的雲，什麼都有，也最複雜、最容易算錯錢。

Azure微軟

微軟的雲，跟 Windows、Office、企業內網整合最好。

Google Cloud

Google 的雲，AI 和資料分析是強項。

看這種圖的三個提醒

一、同一排是「同類」，不是「要全裝」。一排六個圓圈是六個互相競爭的廠牌，通常挑一個。整張圖裝滿是不會發生的事。

二、這是別人畫的分類，不是標準答案。這種生態圖是某個人依他的經驗分的類，換一個人畫會是另外九排。它幫你建立地圖感，不是規格書。

三、圖上沒畫的東西通常更關鍵。這張圖畫的是通用軟體工具。任何一個實際的專案，都會有一批只有自己需要、市面上買不到的環節 —— 那些不會出現在任何一張生態圖上。
