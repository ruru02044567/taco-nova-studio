# 跟王老闆要什麼

> 2026-08-24｜目的：拿到能把資料表定案的三樣東西
> 這三樣拿到，v1 的資料表定義一天內出得來；拿不到，就只能繼續猜他的習慣，
> 而導入失敗最常見的原因就是「系統跟他原本的做法不一樣」。

---

## 一句話版

**要一份 Excel 原檔、一張手寫單的照片、三個問題的答案。**
前兩樣他手上就有，第三樣他站著就能回答。

---

## 給你自己看的部分

### 為什麼一定要「原檔」不要截圖

截圖只有看得見的東西。Excel 原檔裡藏著四樣他自己都不會講的資訊：

| 藏在哪 | 告訴你什麼 |
| --- | --- |
| 公式 | 他怎麼算錢——折扣、運費、湊整數，全在公式裡 |
| 分頁 | 分頁通常就是他的分類：一頁一個月？一頁一種價？一頁一個大客戶？ |
| 隱藏欄 | 曾經需要、後來懶得填的欄位——那是失敗過的流程 |
| 下拉選單 | 他心裡真正的品項清單與狀態清單 |

**他怎麼記，就是系統該長的樣子。**照他的習慣設計，導入阻力少一半。

### 怎麼開口

不要說「我要做系統規劃需要你的資料」——那聽起來像要交作業。

建議的說法：

> 「老闆，你現在記單子的那個 Excel 能不能傳一份給我？我照你原本的樣子做，
> 你才不用重學。客人的名字要遮掉沒關係，**欄位不要刪**就好。」

重點在「照你原本的樣子做」和「不用重學」——這兩句話解決的是他真正的顧慮：
會不會又要學一個新東西。

### 如果他說「很亂，不好意思」

這是最常見的反應，而且**亂才是好事**，要當場講清楚：

> 「亂才有用。整理過的我看不到你實際遇到什麼問題。」

---

## 給王老闆的那一頁（可直接印，或貼 LINE）

### 我需要三樣東西，大概花你十分鐘

**一、你現在記訂單的 Excel 檔（原檔）**

- 用 LINE 或 email 傳檔案本身就好，不用截圖、不用另存新檔
- 客人的名字、電話可以塗掉或改成「客戶A」「客戶B」，**但欄位請不要刪掉**
- 有舊檔案（去年的、前年的）也一起給，愈多愈好
- 如果有好幾個檔案（訂單一個、進貨一個、報價一個），全部都要

**二、一張你手寫單子的照片**

隨便一張都行——出貨單、估價單、便條紙、記帳本的一頁。
拍下來就好，不用挑漂亮的。

**三、三個問題**

| | 問題 | 為什麼問 |
| --- | --- | --- |
| 1 | 批發的客人是**當場付**，還是**月底結一次**？有沒有讓人賒帳？ | 有月結就要多做一整塊對帳功能，現在不知道，之後補會很痛 |
| 2 | 店裡有請人嗎？年節會請臨時工嗎？ | 只有你一個人用，跟三個人一起用，權限跟交接的做法完全不同 |
| 3 | 招牌和發票上的正式店名，是「東信**茶葉**」還是「東信**茶行**」？ | 系統跟網站要統一，現在兩種寫法都有 |

## 收到之後我做什麼

| 時間 | 產出 |
| --- | --- |
| 當天 | 對照他的欄位，補完資料表定義 v1 |
| ＋1 天 | 一份「你的 Excel 每一欄，在新系統長什麼樣」的對照表 |

那張對照表也是**下次見面的談資**：他看到自己熟悉的欄位一欄一欄對過去，
比講任何架構都有說服力。

---

## 順帶要注意的

- **資料一進來就是別人的生意資料。**客戶名單、價格、往來紀錄，
  不要放進任何公開的地方（含公開的 Git repo）。原檔收在本機，
  進 repo 的只能是遮蓋過的欄位結構。
- 這三題問完之前，**不要開價**。痛點清單目前一條都沒驗證過，
  照著報價會變成賣他你以為他需要的東西。
