# BEST_KNOWN_WORKFLOW — 目前已驗證可交付的流程

> 建立 2026-08-13｜**這份寫的是「實際做出已發布影片的流程」，不是理論上最好的流程。**

## ⚠️ 先更正一個假設

原本的指示是「使用目前已驗證的 ControlNet + IP-Adapter」。
但把已發布的 5 支逐支查過 `state.json` 的 `source` 欄位後，事實是：

| 影片 | 實際來源 |
|---|---|
| D1S1 黑洞 | Veo |
| D2S1 巧克力 | 本機 ComfyUI 5 秒單段（Veo 當天逾時） |
| D3S1 淹水 | 本機 ComfyUI 四鏡 12 秒（Veo 額度用完） |
| D4S1 麵粉 | **Gemini 場景圖 → 本機 Wan 2.2 i2v** |
| D5S1 岩漿 | **Gemini 場景圖 → 本機 Wan 2.2 i2v** |

**這 5 支的第一張場景圖全部來自雲端（Gemini／Veo）。**

純本機的 ControlNet + IP-Adapter 路線**從來沒有產出過一支通過 Nova gate 的影片**——
2026-08-13 的 A/B/C/D 實測證實：它能鎖住構圖，但配角一定生成錯誤犬種。

所以：

> **ControlNet + IP-Adapter 是 R&D，不是 Production。**

## ✅ BEST_KNOWN_WORKFLOW v1（目前唯一能過 gate 的）

```
劇本／分鏡
   ↓
Gemini 場景圖（雲端）        ← 角色正確性靠這一步，目前無可替代
   ↓
本機 Wan 2.2 i2v（5 秒單段）  ← auto/make_video_local_5s.py
   ↓
Sonniss 音效 ＋ 正規化 -14 LUFS
   ↓
PUBLISH_GATE 九項檢查
   ↓
待審核／ → 賢賢點頭 → publish_video.py
```

**實測時間**：場景圖（Gemini，人工約 2–3 分鐘）＋ 影片 5.0–5.5 分鐘 ＋ 音效剪接。

### 為什麼不接龍
`make_video_local_5s.py` 的註解寫得很清楚：8/9 三次實測，第二段每次都崩
（長人手／增生第二隻狗／換品種）。**單段 5 秒是本機唯一穩定能交付的長度。**
要更長就每鏡各生一張場景圖分開跑再剪。

## 🟡 可用的變體：純本機（僅限單狗鏡頭）

2026-08-13 訓練出的 LoRA 在**單狗畫面**已驗證可用：

```
ControlNet 深度圖（鎖構圖）
   ＋ Taco LoRA 0.35 或 Nova LoRA 0.35
   → 本機 Wan 2.2 i2v
```

- 單狗特寫／中景：**黑點眉、藍眼、灰白毛都能穩定生出來**
- ❌ **雙狗同框不要用**：LoRA 權重一上去會抹掉災難主體（酒漬、麵粉這類）

**適用範圍**：分鏡裡只有一隻狗的鏡頭。這條路完全離線、不吃額度。

## ❌ 已知不可用

| 路線 | 為什麼 |
|---|---|
| 本機 ControlNet + IP-Adapter 生雙狗 | 配角一定變博美／狐狸犬（A/B/C/D 實測 4/4 失敗） |
| 本機 ControlNet + 雙 LoRA 生雙狗 | 災難主體被抹掉（權重曲線實測） |
| 純文字 prompt 控制構圖 | CLIP 只吃 77 token，長 prompt 會被硬切 |
| 兩段接龍 | 第二段必崩 |

## 升級條件

當 **Nova V2 LoRA** 能同時滿足下面兩項時，才把純本機路線升為 Production：

1. 雙狗同框時 Nova 通過 gate 第 2 條（犬種正確）
2. 同一張圖的災難主體（酒漬／麵粉／土）不被抹掉

驗證方式：拿 D9S1 紅酒場景重跑權重掃描，**看曲線有沒有右移**——
也就是「更高 LoRA 權重仍能保住酒漬」。
