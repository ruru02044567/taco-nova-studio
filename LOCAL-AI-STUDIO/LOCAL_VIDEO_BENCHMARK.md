## 五、⚠️ 執行前的硬體風險（原版 16GB 基準）

**這台的歷史死因是 RAM，不是 VRAM。**

FLUX 生圖實測（8/15、8/16 兩次）：

| 項目 | 數值 |
|---|---|
| 峰值 VRAM | 6.00 GB / 8 GB（沒 OOM，但沒剩多少） |
| **最低可用 RAM** | **0.1–0.3 GB** ← 真正的險處 |
| 開跑前可用 RAM | 5.7 GB（8/15）／**2.6 GB（8/16 現在）** |

**開跑前檢查清單：**

1. 可用 RAM ≥ 6 GB（現在只有 2.6 GB → **必須先關瀏覽器等程式**）
2. ComfyUI 若已載入 FLUX，先確認它有沒有把記憶體讓出來
3. 長任務用 `Start-Process` 獨立跑 ＋ 進度寫 `*.status.txt`，對話斷線不影響
4. 中途要停：`curl -X POST http://127.0.0.1:8188/interrupt`

**B1（1080×1920）的具體風險**：像素量是 704×1280 的 2.3 倍，
VRAM 已經在 6.00/8 GB，**推測會 OOM**。建議先用 VAEDecodeTiled 並從
832×1472 之類的中間尺寸往上試，不要一次跳到 1080×1920。

## 六、參考片基準線（待建立）

收到 Tim & Jeffy Shorts 後要做的第一件事，是用**同一套工具**量出它的數字，
才能跟本機的 0.47 / 0.21 對照：

```
python auto/flow.py     <參考片>    → 光流解釋率
python auto/charstab.py <參考片>    → 角色穩定度
```

有了這三個數字（光流、抖動、角色穩定），「肉眼接近」才會變成可判定的條件，
而不是各說各話。

> 注意：`MODEL_CAPABILITY.md` 的 Veo 錨點是用 d1s1 那支 5.1 萬觀看的片量的。
> 參考片如果比 Veo 更精緻，錨點要重設，能力表的 10 分要跟著調。
