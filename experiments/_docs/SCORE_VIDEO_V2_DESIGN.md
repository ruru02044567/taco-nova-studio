# score_video_v2 設計提案

> 建立：2026-08-21｜狀態：**設計提案。現行 `auto\score_video.py` 一行不改、不取代。**

---

## 一、現行版本沒壞，只是看不到「段與段之間」

`score_video.py` 十項全部是**全片層級**的規格檢查，而且都在做該做的事：

| 現行十項 | 管什麼 | 多段片還準嗎 |
|---|---|---|
| 片長 12.1–14.9s | 對標實測區間 | ✅ 準（本來就是為多段片寫的） |
| 直式 1080x1920 @24fps | 規格 | ✅ |
| 鏡頭數 1–7 | 剪接密度 | ✅ |
| 平均鏡長 ≥1.9s | 同上 | ✅ |
| 主鏡 ≥3.8s | 要有反應戲 | ✅ |
| 整體音量 −25～−16.5dB | 對標實測 | ✅ |
| 峰值 ≥−3.0dB | 打近滿刻度 | ✅ |
| 零靜音段 | 聲底連續 | ✅ |
| 無淡出結尾 | 戛然而止 | ✅ |
| 結尾非定格 | 動作中斷收尾 | ✅ |

**十項一項都不用改。** 問題是**少了一整類**。

### 少的那一類：段間

| 多段片會出的問題 | 現行有沒有在看 | 實例 |
|---|---|---|
| 段間色彩／亮度跳變 | ❌ | 本輪量到 d10s1 **段內**就漂 −9.81 |
| 接縫可見度 | ❌ | scene detect 只數刀數，不評刀口醜不醜 |
| 角色跨段漂移 | ❌ | 8/9「換品種」、8/13「Nova 變博美」 |
| 道具跨段瞬移／消失 | ❌ | 記憶檔：Wan 會讓手上的道具憑空消失 |
| 段內亮度單調漂移 | ❌ | WanVideoWrapper #1541 色偏 bug |
| 藏切有沒有真的藏住 | ❌ | 本輪才第一次量得出來 |

## 二、v2 ＝ 現行十項 ＋ 段間六項，**不是重寫**

```
score_video.py（不動）          ← 全片規格，十項
      ＋
score_shots.py（新增，獨立檔）  ← 段間連戲，六項
```

**為什麼要分成兩支而不是改一支**：

1. 現行那支是**已生效的硬閘門**，改它等於在跑的產線上動刀
2. 段間六項需要知道「接縫在第幾格」——那個資訊來自 `shots.json`，
   而現行 score_video 只吃一個 mp4 路徑，沒有這個輸入
3. 新指標要先累積 5 支片的數字分佈，才知道門檻要定在哪。
   **在有數據之前不設閾值** —— 這是 8/16 `LOCAL_MAX_FAILS = 3` 那次的教訓
   （拍腦袋定的閾值，同日撤回）

## 三、段間六項

輸入：`{key}-cut.mp4` ＋ `{key}_shots.json`（提供每個接縫落在第幾格）

| # | 項目 | 怎麼量 | 建議門檻 | 依據 |
|---|---|---|---|---|
| 1 | **接縫可見度** | `cut_prominence` ＝ 接縫幀差 ÷ 轉場視窗最大幀差 | < 0.5 | 本輪實測：共用遮擋物 0.007、硬切換場景 1.0 |
| 2 | **接縫跳幅** | `cut_ratio` ＝ 接縫幀差 ÷ 段內正常幀差 | < 3.0 | 8/20 實測：正常 1.58、✅ 接法 2.68、❌ 接法 8.58 |
| 3 | **段間色偏** | 各段 RGB 均值兩兩最大差 | < 3.0 | 8/20 接縫診斷用的就是 2.0 這個量級 |
| 4 | **段內亮度漂移** | 每段頭 9 格 vs 尾 9 格亮度差 | \|drift\| < 6.0 | 本輪量到 −9.81（該校）、+3.35、+2.69（可接受） |
| 5 | **角色連續性代理** | 每段的色彩直方圖 vs 第一段的卡方距離 | 待定 ⚠️ | **還沒有基線，先只記錄不設門檻** |
| 6 | **前景面積穩定度** | 前景（vs 時間中位數背景）面積的變異係數 | 待定 ⚠️ | 同上。用來抓「突然多一隻狗」 |

⚠️ 第 5、6 項**明確標為代理指標**：狗轉身、走近鏡頭、光影變化都會讓它們上升。
拿來排名次（哪一支漂得比較多）可以，拿來說「這支崩了」**不行**。

## 四、量不到的東西，老實列出來

**這些永遠不要假裝程式管得住：**

| 量不到 | 誰管 |
|---|---|
| 第三條腿、多餘肢體、沒關節的白肉 | `frame_gate.py` 逐幀人眼硬閘門 |
| 增生第二隻狗 | 同上 |
| 黑點眉在不在、對不對稱 | 同上 ＋ PUBLISH_GATE 角色驗收清單 |
| 笑點成不成立 | 賢賢 |
| 音色自不自然 | 賢賢 |
| 轉場放在這裡合不合理 | 賢賢 |
| 標題承諾對不對得上畫面 | PUBLISH_GATE 第 10 條（人審），未來可由 shots.json 的狀態欄位部分自動化 |

> 8/20 那次事故的教訓不是「該多寫幾條程式」，是
> **「數字類有東西擋所以從不出錯，視覺類沒東西擋所以每輪都在打地鼠」**。
> v2 只補得了數字那一半。視覺那一半的解法是 `frame_gate.py`，那支已經在了。

## 五、落地順序

| 步 | 做什麼 | 停得住嗎 |
|---|---|---|
| 1 | 寫 `score_shots.py`，**只印報告、永遠 exit 0** | ✅ 完全無害 |
| 2 | 對**已發布**的 d9s1 / d11s1 / d12s1 / d10s1-cut 四支回頭跑，收集數字分佈 | ✅ 唯讀 |
| 3 | 用那四支的分佈訂第 1–4 項的門檻（第 5、6 項繼續只記錄） | ✅ |
| 4 | 新片開始跑，但仍 exit 0，累積 5 支 | ✅ |
| 5 | 賢賢裁示後，才接進 `finish_video.py` 變硬閘門 | 需賢賢裁示 |

⛔ 第 5 步之前，`finish_video.py` 一行不改。
⛔ 任何時候都不動 `score_video.py` 的十項。
